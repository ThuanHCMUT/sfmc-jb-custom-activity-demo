## 1. Symptom and root cause

**Symptom.** The custom activity endpoint was added in Marketing Cloud, but the activity does **not show up in the
Custom Activity palette** in Journey Builder.

**Root cause.** `GET /config.json` (generated by `server/services/activity-config-builder.js`) deviates from the
official Salesforce sample in four ways that prevent Journey Builder from registering/listing the activity:

| # | Deviation | Effect |
|---|---|---|
| 1 | **Top-level `name` (and `description`) are missing.** The builder emits only `lang.en-US.name`. | The SFMC custom activity spec requires a top-level `name`; Journey Builder uses it to register and list the activity. Missing it is the most probable cause of "not showing". |
| 2 | **`userInterfaces.configModal.url` is missing.** The builder emits `{ fullscreen: true }` only. | Journey Builder cannot open the configuration modal; the activity is treated as incomplete/unusable. |
| 3 | **`metaData.category` is `"message"` instead of `"Custom"`.** | The activity is grouped under **Messages** in the palette, not under **Custom** where it is expected. |
| 4 | **`useJwt: true` is used instead of `securityOptions.securityContext`.** | The official sample (and current SFMC) expresses JWT protection as `securityOptions: { securityType: "securityContext", securityContextKey: "<External Key>" }`. The legacy `useJwt` flag is not honored the same way on current instances, so JWT-protected lifecycle calls fail. |

Secondary alignment items from the sample (recommended, not blockers): top-level `description`, `copySettings`
(`allowCopy`, `ignoreArguments: ["eventDefinitionKey"]`), and (optional) example `inArguments`/`outArguments`
values plus `runningModal`/`runningHover` URLs.

## 2. Change 1 — `server/services/activity-config-builder.js`

### 2.1 Signature

```js
// before
export function buildActivityConfig({ publicBaseUrl, requireJwt }) {

// after
export function buildActivityConfig({ publicBaseUrl, requireJwt, securityContextKey }) {
```

### 2.2 Security helper (replaces `lifecycle`/`useJwt`)

```js
// before
const url = (path) => `${publicBaseUrl}${path}`;
const lifecycle = (path) => ({ url: url(path), useJwt: requireJwt });

// after
const url = (path) => `${publicBaseUrl}${path}`;
const securityOptions = requireJwt
  ? { securityType: 'securityContext', securityContextKey: securityContextKey || '' }
  : null;
const lifecycle = (path) =>
  securityOptions ? { url: url(path), securityOptions } : { url: url(path) };
```

### 2.3 Top-level fields, metaData, execute, userInterfaces, copySettings

```js
return {
  workflowApiVersion: '1.1',
  name: 'Notification Hub',                                    // NEW (required by SFMC)
  description: 'Send a notification through Notification Hub.', // NEW
  metaData: {
    icon: url('/assets/icon.svg'),
    category: 'Custom',                                        // CHANGED: 'message' -> 'Custom'
    isConfigured: false,
  },
  type: 'REST',
  lang: {
    'en-US': {
      name: 'Notification Hub',
      description: 'Send a notification through Notification Hub.',
    },
  },
  arguments: {
    execute: {
      inArguments: [],
      outArguments: [],
      url: url(LIFECYCLE_PATHS.execute),
      verb: 'POST',
      ...(securityOptions ? { securityOptions } : {}),        // CHANGED: useJwt -> securityOptions
      timeout: 20000,
      retryCount: 2,
      retryDelay: 1000,
      concurrentRequests: 6,
    },
  },
  configurationArguments: {
    save: lifecycle(LIFECYCLE_PATHS.save),                     // now carries securityOptions
    validate: lifecycle(LIFECYCLE_PATHS.validate),
    publish: lifecycle(LIFECYCLE_PATHS.publish),
    stop: lifecycle(LIFECYCLE_PATHS.stop),
  },
  wizardSteps: [{ label: 'Configure notification', key: 'step1' }],
  userInterfaces: {
    configModal: {
      fullscreen: true,
      url: url('/'),                                           // NEW: modal URL (was missing)
    },
  },
  schema: {
    /* unchanged: fixed keys source, channel, templateKey, templateVersion, eventDefinitionKey */
  },
  copySettings: {                                              // NEW (per sample)
    allowCopy: true,
    ignoreArguments: ['eventDefinitionKey'],
  },
};
```

Notes:
- `configModal.url` points at the public root (`index.html`), which is where the Postmonger UI is served
  (README: "Set the activity endpoint to the public root URL, which serves `index.html` and `config.json`").
- `runningModal` / `runningHover` are optional; add them later only if a custom running indicator is wanted.

## 3. Change 2 — `server/config.js` (new `SFMC_SECURITY_CONTEXT_KEY`)

Add the External Key of the Installed Package's **JWT Signing** component so the builder can emit
`securityOptions.securityContextKey`:

```js
// in loadConfig, after the jwtSecret block:
const securityContextKey = env.SFMC_SECURITY_CONTEXT_KEY ?? '';
if (isProduction && requireJwt && !securityContextKey) {
  problems.push('SFMC_SECURITY_CONTEXT_KEY is required in production when SFMC_REQUIRE_JWT is true.');
}
```

Add to the returned frozen config object:

```js
securityContextKey,
```

Update the production mode table in the README (build-agent follow-up; README is outside `docs/`):

| `SFMC_SECURITY_CONTEXT_KEY` | optional | required when JWT enabled; the External Key of the JWT Signing component in the Installed Package |

## 4. Change 3 — `server/routes/config.routes.js`

Pass the new value through:

```js
// before
const definition = buildActivityConfig({ publicBaseUrl: config.publicBaseUrl, requireJwt: config.requireJwt });

// after
const definition = buildActivityConfig({
  publicBaseUrl: config.publicBaseUrl,
  requireJwt: config.requireJwt,
  securityContextKey: config.securityContextKey,
});
```

## 7. Verification

1. `npm test` — all suites green (updated assertions).
2. `GET /config.json` returns the shape in §6; `name`, `category: "Custom"`, `configModal.url` and
   `securityOptions` present.
3. Development (`SFMC_REQUIRE_JWT=false`): no `securityOptions` anywhere; `name`/`category`/`configModal.url`
   still present.
4. In Marketing Cloud: refresh the Custom Activity palette — the activity appears under **Custom**.
5. Open the activity: the config modal loads from `configModal.url`; save/validate/publish/stop calls carry a
   valid JWT signed with the Installed Package secret and are accepted by the JWT-signing component whose
   External Key equals `SFMC_SECURITY_CONTEXT_KEY`.
